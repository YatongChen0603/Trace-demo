TRACE: From Slow Thinking to Fast Execution for Mobile Embodied Agents

Guided parking on the vehicle testbed, one recorded trial. A person standing outside names a bay by speech and gesture. The 2B on-device brain never receives a pixel directly: it chooses which sensing tool to spend its budget on, and commits to slot_4 after six calls and 3.6 seconds. Overlays are the site's bay map, the arm bearing recovered by the gesture tool, and the committed bay. Faces are blurred in every recording on this page.

Abstract

Making models smaller does not necessarily make embodied agents efficient. Even with a compact model, an agent remains slow when it must call the model after every sensing or action step. Many tasks repeat the same decisions, but their next steps still depend on current sensor results, so an answer cache or fixed workflow cannot replace the model loop.

We introduce task-level compute reduction: turning repeated successful decision patterns into executable on-device fast paths. TRACE compiles these patterns into guarded graphs that choose the next step from live tool results, and returns control to the model when no graph applies or execution deviates. Cloud training initializes TRACE, while all task execution remains on the device without runtime cloud connectivity.

Across four public datasets, three simulation datasets, and two physical testbeds, TRACE reduces end-to-end latency by 42.7% while preserving task accuracy, and avoids up to 51.1% of model invocations and 45.5% of generated tokens. These results show that task-level compute reduction complements model compression for efficient on-device embodied intelligence.

Task-Level Compute Reduction

Practice turns repeated step-by-step reasoning into direct skill execution.

Quantization, pruning, and distillation lower the cost of each model call. They do not stop an agent from processing streams the task never needed, or from rebuilding a procedure it has already carried out successfully many times. Task-level waste has these two sources:

  • Perception cost is wasted when the agent processes streams unrelated to the task.
  • Reasoning cost is wasted when the agent reconstructs a familiar multi-step procedure it has executed before.

Humans connect the two through practice: deliberate attention first identifies which evidence matters, and recurring perception-action procedures gradually become automatic. TRACE follows the same cycle. It reasons through unfamiliar tasks to decide what to sense, then consolidates the successful recurring chains so familiar tasks avoid both unnecessary perception and repeated reasoning. Because the next step still depends on what the last tool returned, the consolidated form has to be a guarded graph rather than a cached answer or a fixed workflow.

System Overview

Cloud training initializes the brain, the compiler, and the skill library. After deployment, query execution and skill-graph updates run on the device.
  1. One tool interface for sensing and action. Cameras, microphones, depth, inertial streams, trackers, and the arms themselves are typed JSON tools behind long-lived HTTP services. A YAML contract lists each scenario's tools, schemas, and endpoints, so adding a sensor changes configuration rather than agent code. The pool holds 66 tools and each scenario uses between 7 and 20 of them.
  2. Deliberation that ends in a committed act. The 2B brain is trained by distillation from a 30B omni-modal teacher and then by reinforcement learning against outcome rewards, so an unfamiliar task produces a chain that ends in an answer or an action rather than a description.
  3. Compilation into a guarded graph. The compiler keeps the calls, their order, the branches, and the guards that decide when each applies, and drops the prose. The executor and guard evaluator are plain Python, under 300 lines, and need no GPU. Graphs live in a SQLite library with their retrieval embeddings, which adds 0.1 GB of storage.
  4. Serving by measured outcome, with a way back. A gate decides between replay and deliberation, guards abort a replay that deviates, and a fallback returns control to the model. Removing the fallback collapses mean accuracy from 67.9% to 29.9%, which is what makes this a system rather than a cache.

Against existing methods. Baselines that reprocess streams or rerun predefined sensing spend 11.6 to 14.6 tool calls and 91.1 to 96.1 seconds per query; CoMIC and TaskSense reach 105.6 and 95.8 seconds because their request-time guidance involves a 27B cloud model. AWM has the strongest external mean at 50.5% but still needs 84.6 seconds and 10.5 calls, since retrieved workflows must be interpreted for each query. TRACE reaches 67.9% in 22.4 seconds with 3.44 calls, improving on AWM by 17.4 points while cutting latency by 73.5% and tool use by 67.2%.

Student against teacher. The 2B model exceeds its 30B teacher by 8.8% overall and wins on HoloAssist, RealSource, RealMan, and CARLA, by 43.2% on RealMan and 18.3% on CARLA. These interactive tasks reward collecting evidence and acting on it rather than answering from prior knowledge. The teacher stays 4.0 to 4.4% ahead on Ego-Exo4D, OmniVideo, and HM-EQA.

Model size and serving. The 0.8B model finishes in 16.0 seconds but makes fewer calls and loses 13.6 points, exploring too little before answering. Disabling skills keeps 66.6% accuracy but raises latency to 39.1 seconds. The 2B brain supplies the reasoning capacity; skill reuse supplies the speed.

One slip, stated plainly. In its last turn the model calls 0.02 m “the gap” and concludes it is in the unreliable regime. The gap to the next free bay is 2.25 − 0.02 = 2.23 m, which is the reliable one. The arithmetic is wrong and the conclusion is right; calling this chain flawless would be overclaiming.

Code and Data

The prototype is over 15,000 lines of Python on PyTorch, verl, and vLLM. Tools run as long-lived HTTP services with typed JSON interfaces, so each specialist model loads once and is shared across training, evaluation, and serving. Training uses two NVIDIA RTX 6000D GPUs; edge measurements run the model, the skill executor, and the tools on an NVIDIA DGX Spark. The skill library is a SQLite file holding each graph as canonical JSON with its retrieval embedding, which makes a library easy to copy and evaluate reproducibly.

Code, the skill libraries, and the recorded vehicle and cabin sessions will be released after review. This page carries no author or institution identity until then.
