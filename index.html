CRAFT: Compiling Proactive Sensing Experiences into Executable Skills for Mobile Embodied Agents

A mobile agent that decides what to sense next pays for a model generation after every sensing step. CRAFT compiles the chain it already reasoned out into an executable skill, and the device replays that skill with no model inference between sensing calls.

Abstract

Mobile embodied agents operate in physical environments where task-relevant information is dispersed across heterogeneous sensors, may appear only briefly, and can sometimes be obtained only through physical interaction. This calls for proactive sensing: deciding at runtime what to sense or do next based on observations collected so far. However, invoking the model after every sensing step incurs substantial latency and energy overhead and may cause the agent to miss the narrow time window in which transient evidence is available.

We observe that different task instances often require similar sequences of sensing and action. Building on this observation, we present CRAFT, a proactive-sensing framework that uses cloud compute during training to build a skill compiler and an initial skill library, then deploys both on the mobile device. At runtime, all processing remains on the device: tasks matched to a reliable skill execute it locally without model inference between sensing steps, whereas unmatched tasks fall back to on-device model deliberation. A common tool interface unifies sensing and action, while outcome-based skill selection and confidence-aware fallback sustain the system reliability.

Across seven embodied datasets and two physical testbeds spanning vehicles, robots, and wearables, CRAFT reduces end-to-end latency by 42.7% while preserving task accuracy. These savings grow with the number of sensing steps, avoiding up to 51.1% of model invocations and 45.5% of generated tokens.

Why a device cannot just encode everything

Evidence in a physical scene is sparse, brief, and spread across sensors that each cost something to read. Encoding all of them on every round is both wasteful and too slow to catch the moment that mattered.

How CRAFT works

The cloud thinks each kind of task through once. The device replays what that thinking produced, and falls back to thinking whenever the match is not trustworthy.

1

One tool interface for sensing and action

Cameras, microphones, depth, IMU, gaze, trackers, and the arms themselves are all typed JSON tools behind long-lived HTTP services. Adding a sensor changes a YAML contract, not agent code, so the same brain moves between a car, an arm, and a headset.

2

Deliberate once, in the cloud

The brain is trained by distillation from a large omni-modal teacher and then by reinforcement learning against outcome rewards, so a chain ends in a committed answer or action rather than in a description of what it saw.

3

Compile the chain into a skill graph

The compiler keeps the calls, their order, and the guards that decide when a branch applies, and drops the prose. The executor and its guard evaluator are plain Python, under 300 lines, and need no GPU. Graphs live in a SQLite library with their retrieval embeddings.

4

Serve by measured outcome, not by similarity alone

A skill is admitted, kept, or evicted on what it actually scores. At serving time a gate decides between replay and deliberation, and a confidence-aware fallback catches the cases replay should not own. Removing that fallback costs 38 points of mean accuracy, which is what makes it a system rather than a cache.

One slip, stated plainly. In its last turn the model calls 0.02 m “the gap” and concludes it is in the unreliable regime. The gap to the next free bay is 2.25 − 0.02 = 2.23 m, which is the reliable one. The arithmetic is wrong and the conclusion is right; calling this chain flawless would be overclaiming.

What limits the real-car number. These rows run the lane where the gesture tool returns the labelled bay's bearing plus the noise the training environment adds, and a procedure-perfect chain there reaches 91.2%. In the harder lane, where the bearing is recovered from the arm in the forward camera, the reading carries a median error of 18.8 degrees, a procedure-perfect chain reaches only 36.9%, and CRAFT reaches 17.1%. The gesture reader, not the policy, is what that lane is measuring.
